# v0.15.0-patched.1

Upstream v0.15.0 (was v0.14.0), patches 0001-0055. The first release on v0.15: upstream's
components, libraries, workspace seats and stall watchdog, with our patches rebased onto it.

## Before deploying

- **Take a database dump.** This release runs 11 upstream migrations, 0049-0059: image
  descriptions, instance settings, custom providers, components and libraries, work replies,
  custom agents, component soft delete and workspace seats.
- Our own three migrations are renumbered 0060-0062 and keep their timestamps, so a database
  that already has them skips them. drizzle's migrator would also have skipped upstream's
  0049-0059, which are stamped earlier than ours. Patch 0053 applies by version set instead,
  every missing migration in one transaction.

## Deploying

- Dependencies added: `cmdk`, `css-select`, `zod-to-json-schema` (in `package.json` and
  `bun.lock`, installed by the image build). The Dockerfile is unchanged.
- No new required environment. New optional settings are listed in upstream's `.env.example`:
  `STALL_*`, `SLOW_OP_LOG_MS`, `RENDER_CONCURRENCY`, `REMOTE_BROWSER_*`, `DESCRIBE_*`,
  `CANVAS_IDLE_MS` and the work-budget limits.
- **Stall watchdog.** In production the server kills itself (SIGKILL) when its event loop has
  not answered for 60 s (`STALL_EXIT_MS`, default 60000). It expects the supervisor to start
  it again. Make sure the service restarts on exit, or set `STALL_EXIT_MS=0` to turn it off.
- Frame HTML is now loaded per canvas when it is opened, and dropped after 10 idle minutes
  (`CANVAS_IDLE_MS`). Memory falls on an instance with many canvases. The first open of a
  cold canvas reads it from the database.

## Checking

- The server boots without a migration error. On a database that had v0.14.0-patched.N,
  `select count(*) from drizzle.__drizzle_migrations` goes from 52 to 63.
- A canvas opens and its frames render. Signed out, `/api/operator` is still refused.

## Rolling back

- Point the deployment back at `v0.14.0-patched.21`. The database can stay: the new tables
  and columns are additions that v0.14 ignores.
- Restore the dump only if a migration failed partway. Restoring after people have used v0.15
  loses their edits since the deploy.
